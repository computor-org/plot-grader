# Round 5: the round-4 judge on real 2026 submissions

Tables in sections 1–3 are from `scripts/report_real2026.py`
(`data/vlm_eval/r5/aggregates.md`), run by `scripts/run_real2026.sh`.
Sections 4 and 5 are hand analysis of the rows. Raw rows, renders and the
manifest are in `data/` (gitignored); this file holds aggregates only.

**No human labels exist for these submissions yet.** Every number below is
agreement with the official graphics tests, not accuracy. Round 4 showed that
the tests themselves agree with the visual criteria only 0.68 of the time, so
a low agreement here does not say which side is wrong.

## Setup

- **Data:** the latest submission per student and exercise from the 2026
  PiP course (`scripts/build_real2026.py`): 130 students, 17 exercises,
  1870 submissions. Excluded: 44 render errors, 2 without an entry file.
  Judged: 1824. The label is the official harness result for the graphics
  tests.
- **Judge (round-4 rule):** Flash-Next (self-hosted, chat, temperature
  0.1, reasoning off) with the `pair_tolerant` prompt must say PASS, **and**
  `tolerant_check()` (`src/plot_grader/tolerant.py`) must report no problem.
  The checks run offline in the report from the extracted plot data.
- **Comparison:** the strict `pair` prompt once, and Tier 1 (data) from the
  rows.
- Images at 75 %, one repetition each.
- **Parallelism:** the run script now says `--workers 1`, but the rows record
  16 parallel requests for all 1824 tolerant calls and 1582 of the 1824 strict
  calls. Only the resumed tail (242 strict calls, 6 tolerant reruns) ran with
  one worker. See section 6.
- **Resume:** `--resume` appends to `rows.jsonl`. The tolerant file has 1830
  rows: 6 calls first failed with unparseable JSON (4 with an invalid
  `\` escape, 1 without a JSON object, 1 with an unterminated string) and were
  rerun successfully. The latest row per (view, rep, case) counts, which
  leaves 1824 per run. 3 strict calls stay unusable (HTTP 503).

## 4. Why the five exercises disagree

Found by grouping the failed graphics tests, the check problems and the
model's `differences` per exercise, and by comparing the extracted plot data
with the reference. Nobody has looked at these plots by eye yet.

| exercise | cause | who is wrong |
|---|---|---|
| basis2 | 104 of 105 test failures are only `get_title()`; 92 students use the German title of the task sheet where the reference has the English one | tests (criteria: wording may differ) |
| simple_taylor | 103 of 105 test failures are only the four subplot titles; 87 are the German titles | tests |
| pi_random | checks report "curve 0 not found" in 74/75 cases; the model passes 73/75 | checks: unseeded Monte-Carlo, a new draw never matches the reference data (round-4 criterion T6) |
| cosine_function | the model passes 110 of the 113 test-passing plots; the checks report "curve 0 not found" in 71 cases, 69 of which store that curve as complex numbers (`(1+0j)`) | checks: they cannot read complex y data, the curve is the same |
| series_expansion | 56 of 106 plots have no axis labels while the reference labels `x`, `y`; the checks flag them (M4), the tests do not test labels. The model fails 45 test-passing plots, claiming different curves | model, and possibly the checks |

Details for series_expansion: the checks find every reference curve in the
student data, so the curves are the same. The model's reasons are M2
"visibly different shape" claims that contradict each other from case to
case (in some the reference is the sine expansion, in others the cosine
expansion). 99 of 106 students use a y range of ±3.5 against ±2 in the
reference; the likely trigger is that different visible range, which the
tolerant prompt should accept. Whether missing axis labels fail the plot
depends on whether the task asks for them; under `docs/criteria.md` (a
labelled axis stays labelled) the checks are right, and the tests are not
checking it.

Smaller groups, not resolved:

- **linalg_conic_sections** (32 tests FAIL, judge PASS): the tests fail on
  line data and on two collections (arrow vectors `_vec`, path
  vertices). The tolerant checks
  compare lines only, and the strict model fails 31 of the 32. Likely
  judge too tolerant; needs the human check.
- **beat_oscillation** (25): tests fail everything in both figures
  (`figure(1)` and `figure(2)`); the rendered image shows only one axis.
  The judge may not see what the tests test; needs a look at the figure
  handling.
- **kerr_cell** (18) and **week3_summary** (16): tests fail on single
  lines (data, colour, marker); several students draw more or fewer lines
  than the reference. Mixed; strict model splits both.
- **lab_exercise1**: tests and judge agree that 106 of 117 plots FAIL
  (tests: line data and title; checks: x range hides the data). A
  reference or task problem is more likely than 106 wrong students; worth
  checking with the exercise owner.

## 6. Speed

The throughput lines in `aggregates.md` are wrong for resumed runs:
`wall_s` covers only the last session, but `calls` counts all rows (hence
"918.6 calls/min"). From `workflow.log` and the rows instead:

| run | parallel | calls | wall | calls/min | p50 s |
|---|---|---|---|---|---|
| tolerant | 16 | 1824 | 62 min (07:14–08:16, one restart) | ≈ 29 | 30.1 |
| strict | 16 | 1582 | ≤ 58 min (08:16, stopped before 09:14) | ≥ 27 | 31.9 |
| strict, resumed tail | 1 | 242 | 16 min (09:16–09:32) | ≈ 15 | 3.6 |

At 16 parallel requests the 30 s median is queueing on the server, not model
time; one request alone takes about 4 s, as in round 3. One Mac judges the
course's final submissions (≈ 1800) in about an hour for the tolerant pass.

## Limitations

- **Agreement, not accuracy.** The tests are not ground truth (round 4:
  0.68 against visual labels). The "who is wrong" column in section 4 is
  inferred from data and model reasons, not from looking at the plots.
- **The independent human check is still due.** Two human raters
  label a blind sample in October: `data/real2026/sample_for_human.jsonl`,
  80 cases (20 tests PASS/judge FAIL, 20 tests FAIL/judge PASS, 40 where
  both agree), with the key in `sample_key.jsonl`. All 579 disagreements
  are in `disagreements.jsonl`. The sample is small for per-exercise
  conclusions.
- One repetition per case; round 4 found 239/244 identical verdicts over
  two runs, so a few percent of single verdicts may flip.
- The judge sees one rendered image per submission. Exercises with two
  figures (beat_oscillation) may be judged on less than the tests check.
- 46 submissions (2.5 %) that did not render or had no entry file are
  excluded.
- Only final submissions; earlier attempts in the course are not covered.
- The tolerant prompt and the check thresholds were tuned on the 244
  round-4 cases, not on real submissions.

## Conclusions

- **On real submissions the combined judge agrees with the tests on 0.68
  of 1824 cases**, the tolerant model alone on 0.76, the strict prompt on
  0.67, Tier 1 on 0.62. This matches the round-4 picture: tests and judge
  differ by design on wording and tolerance.
- **Most disagreement sits in five exercises (408 of 579).** Elsewhere the
  judge and the tests agree on 0.87.
- **Tests wrong, judge right (probably):** basis2 and simple_taylor fail
  about 100 students each only because the title is the German one from the
  task sheet. The tests should accept either language, or the title test
  should go.
- **Checks wrong, model right:** pi_random (unseeded random data, known
  from round 4) and cosine_function (complex-valued y data the checks cannot
  read). Both are fixable in `tolerant.py`: skip curve matching for
  unseeded exercises, take the real part of complex data. With both fixed
  the judge would agree on 0.75.
- **Model wrong:** series_expansion, where the model invents different
  curves for plots whose data match the reference, most likely because of
  the wider y range. The missing axis labels (56 plots) are a real
  difference that the tests ignore.
- **Open:** linalg_conic_sections (judge probably too tolerant with
  vectors and filled paths), beat_oscillation (second figure), and
  lab_exercise1 (both fail 106 of 117; check the reference).
- **Next:** fix the two check bugs, fix the throughput accounting for
  resumed runs, and wait for the human labels before choosing between the
  tolerant model alone and the combined rule.

## Addendum: check bugs fixed (same day)

Both bugs are fixed in `src/plot_grader/tolerant.py`, with tests in
`tests/test_tolerant_judge.py`:

- complex-valued data (numbers or strings like `(1+0j)`) is compared by its
  real part, as matplotlib plots it;
- `unseeded_random(source)` detects a reference solution that draws random
  numbers without a fixed seed (criterion T6), and `tolerant_check(...,
  random_data=True)` then leaves the curve values to the model. Of the 17
  exercises only pi_random is detected.

`aggregates.md` is regenerated with the fixed checks (the old one is kept
as `aggregates_v1.md`). The combined judge now agrees with the tests on
1360/1824 (0.75), as the what-if in section 5 predicted. The throughput
lines now count only the calls timed in the last invocation.

Re-scoring round 4 with the fixed checks (same model rows, same blind
labels, `scripts/report_round4.py`): tolerant model and checks 0.97 with
5 false passes and 3 false fails, against 0.93 (3 and 13) before. The
10 removed false fails are the unseeded Monte-Carlo exercise; 2 wrong plots
of it now pass because only the model judges its curves. T6 was part of the
criteria before round 4, but the fix was written after seeing these
results, so the 0.97 is not an independent measurement; the October human
labels are.
